# Nestory 모바일 디자인 연구

2026년 10월 1일 기준, [Issue 3](https://github.com/YunFlutter/nestory/issues/3)의 디자인 제안을 위한 연구다. 대상은 한국어를 사용하는 Android·iPhone 사용자이며, [MVP 기획](PRODUCT_PLAN.md)의 등록·찾기·이동 흐름을 유지한다. 현재 앱은 카운터 템플릿이므로 기존 제품 화면의 사용성 개선 실측이 아니라 구현 전 디자인 연구다.

## 연구 결론

Nestory에는 사진이 주인공인 밝은 화면, 읽기 쉬운 한글, 현재 위치를 드러내는 경로, 짧은 상태 전환을 권장한다. 차분한 청록을 주요 동작에, 따뜻한 살구색을 작은 브랜드 그래픽에 사용하는 방향을 제안한다. 이는 한국인의 색 선호에 대한 조사 결과가 아니라 제품 용도와 공개 디자인 자료를 종합한 판단이다.

높은 완성도는 공통 규칙과 예외 상태까지 일관되게 적용해 확인한다. 수상 여부나 등록·검색 속도 개선은 이번 연구로 보장하지 않는다. Web 지원, 대시보드, 공유, AI 인식 등 기획에 없는 기능을 추가하지 않는다.

60fps 목록과 개별 페이지, 공개 사례 설명을 열어 확인했다. 인앱 브라우저에서 화면 캡처가 실패했으므로 영상의 전체 재생, 정확한 간격·모션 곡선·전환 시간은 검증하지 못했다. 위 적용안은 상세 시각 복제나 영상 QA 결과가 아니다. 사용자 인터뷰와 사용자 불만의 빈도 조사도 수행하지 않았다.

## 한국어 화면 기준

- 공간·보관함·물건이라는 기획 용어를 유지한다. UI에서 inventory, container, draft 같은 영어를 섞지 않는다.
- 이름·위치처럼 필요한 정보는 고정 레이블로 제공하고 안내 문장만 줄인다. 긴 한글 이름과 경로는 줄바꿈 및 전체 값 확인 경로를 설계한다.
- 사진이 없는 등록도 완전한 동작으로 취급한다. 회색 아이콘과 유형 레이블을 사용하고 사용자 사진처럼 보이는 가짜 사진을 채우지 않는다.
- `저장`, `이 위치로 이동`, `계속 작성`처럼 행동을 드러내는 버튼을 사용한다. 오류는 원문 대신 유지된 내용과 다음 행동을 설명한다.
- 색·서체·간격의 역할을 모든 화면에서 공유한다. 화면별 색 테마보다 사진과 정보 구성으로 화면의 개성을 만든다.

| 위치 상세 | 눌러 이동하는 경로, 내부 보관함 먼저, 바로 속한 물건 아래 | 계층 진입·뒤로 가기의 방향 일관성 | 공간 아래 보관함 최대 2단계, 사진 없이도 구분 |

| 검색 결과 | 사진·이름·전체 경로가 있는 행, 이름 일치 우선·최근 수정순 전환 | 과한 결과 순차 공개 없이 빠르게 표시 | 단어 조합·부분 일치 규칙 유지, 캐시 결과 범위 표시 |
| 물건 상세 | 사진과 이름 다음에 현재 위치를 강조, 메모와 이동·수정·삭제 | 같은 사진이 상세로 이어지는 전환 | 이동 기록 기능을 추가하지 않고 현재 위치에 집중 |
| 위치 선택과 이동 | 현재 경로와 선택 목적지를 함께 표시, 명시적인 확정 버튼 | 서버 성공 후 경로 갱신과 짧은 완료 피드백 | 보관함 내용물도 함께 이동, 진행 중 취소 상세 규칙은 후속 Issue |
| 임시 저장 | 계정의 초안 하나, 이어쓰기·삭제, 기기 보존·서버 동기화 상태 | 저장 상태를 필요한 순간에만 갱신 | 기기 보존을 서버 저장 완료로 표현하지 않음 |
| 로그인과 계정 | 이메일·비밀번호 레이블, 재설정·가입·탈퇴 흐름 | 입력을 방해하지 않는 최소 전환 | 소셜 로그인 추가 없음, 탈퇴 비밀번호 재확인 |
| 삭제 확인과 오류 | 대상과 복구 불가를 분명히 설명, 실패 원인에 맞는 행동 | 의미 전달에 필요한 최소 전환 | 복구·실행 취소를 제안하지 않음, 빈 위치만 삭제 |

## 구현 부담과 우선순위

우선 공통 토큰, 검색창·입력·행·카드·상태 안내를 적용한다. 다음으로 홈 → 위치 상세 → 물건 등록 → 검색 → 이동을 함께 검증한다. 사진 공유 전환과 시트 전환은 그 흐름이 안정된 다음 추가한다. 3D 실시간 렌더링, 화면 전체 블러와 계속 재생되는 배경 효과는 초기 MVP에 권장하지 않는다. 이는 측정 전 설계 판단이며 특정 기기의 성능 결과가 아니다.

모션은 [Flutter의 애니메이션 축소 설정](https://api.flutter.dev/flutter/animation/AnimationBehavior.html)을 존중하고 [profile 모드의 성능 도구](https://docs.flutter.dev/tools/devtools/performance)에서 확인한다. 기획의 등록 30초·찾기 10초는 사용자 5~10명을 관찰할 때의 목표이며 이번 연구의 달성 결과가 아니다.

디자인 시스템은 [별도 제안 문서](DESIGN_SYSTEM.md)에서 구체화한다. 최종 색상과 시각 방향은 사용자 검토 후 확정한다.
