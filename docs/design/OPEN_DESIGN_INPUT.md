# OpenDesign 입력 자료

[Issue 3](https://github.com/YunFlutter/nestory/issues/3)의 Nestory 디자인 제안을 OpenDesign의 디자인 시스템 생성 화면에 입력하기 위한 자료다. 색·수치는 [원본 디자인 시스템](../DESIGN_SYSTEM.md)을 따른다. 그린 계열·AI스럽게 느껴지는 장식 조합·웜화이트 배경을 제외하고 순백색·무채색 회색·차콜 기준을 유지했다.

## Describe brand

아래 코드 블록의 내용만 `Describe brand`에 붙여 넣는다.

```text
Nestory는 집 안의 물건을 기록하고 현재 보관 위치를 쉽게 찾는 한국어 모바일 앱입니다. Android와 iPhone을 대상으로 공간 → 보관함 → 물건 구조의 등록·찾기·이동을 돕습니다. 이름과 전체 위치 경로가 핵심이며 사진은 선택적인 단서입니다.

국내 생활 서비스의 일상적인 모바일 사용 흐름에 어울리는 명료하고 친근한 UI를 원합니다. 순백색 #FFFFFF 바탕, 밝은 무채색 회색 영역 구분, 읽기 쉬운 차콜 한글과 버튼을 사용해 주세요. 브릭 #985343은 작은 브랜드 표식에만 사용합니다. 그린 계열, 블루·보라 테크 브랜드 조합, 웜화이트·크림·베이지 배경, 파스텔 카드, 그라데이션, 광택 3D 소품은 제외합니다.

한글 서체 후보는 Pretendard입니다. 설명은 짧은 해요체, 버튼은 저장·계속 작성·이 위치로 이동·재시도처럼 명확한 행동으로 작성합니다. 화면의 완성도는 정렬·간격·정보 위계·공통 컴포넌트와 실패 상태의 일관성으로 표현해 주세요. MVP에 없는 AI 인식·가족 공유·QR·대시보드·금액 관리 등을 추가하지 마세요.
```

## Paste DESIGN.md

저장소 루트의 [DESIGN.md](../../DESIGN.md)를 열고 **첫 줄 `---`부터 마지막 줄까지 전체 내용**을 붙여 넣는다. 이 파일 자체를 추가 코드 블록으로 감싸지 않는다. YAML 앞부분에 역할별 색·서체·간격·형태·모션 토큰이 있고 본문에 컴포넌트·상태·한국어 문구·생성 제약이 있다.

입력창의 Heritage 예시를 덮어쓴다. 다른 브랜드 시스템을 복사할 필요는 없다. `GitHub or website`는 이번 붙여넣기 방식에서는 비워둘 수 있다. 현재 저장소의 main 앱은 Flutter 카운터 템플릿이므로 해당 화면을 제품 스타일 원본으로 추출하지 않는다.

## Add files

선택적으로 [최신 디자인 시스템 보드](nestory-design-system-board.png)를 추가한다. 흰 바탕과 무채색 회색으로 수정한 보드만 사용한다. 이미지의 색·글자·서체 모양보다 DESIGN.md의 정확한 토큰을 우선한다. 이미지에는 기본 바탕을 `순백색`으로 표기했으며 실제 값은 #FFFFFF다.

폰트 파일은 이번 작업에 추가하지 않았다. 생성 미리보기의 Pretendard 실제 적용 여부는 결과에서 확인해야 한다.

## Advanced → Notes

아래 내용만 `Notes`에 붙여 넣을 수 있다. 같은 핵심 제약은 DESIGN.md에도 들어 있다.

```text
DESIGN.md를 색·서체·컴포넌트의 기준으로 사용하세요. Android·iPhone용 한국어 모바일 UI kit와 컴포넌트 상태를 구성하고 데스크톱 웹 랜딩 페이지·iPad·대시보드는 만들지 마세요. 페이지·카드·시트·상태 안내의 기본 바탕은 #FFFFFF입니다. 보조 영역은 #F5F5F5, 선택 영역은 #F4F4F4이며 베이지 배경으로 바꾸지 마세요.

홈은 검색창·공간 카드·공간 추가 중심입니다. 위치 상세는 전체 경로·보관함·물건 섹션으로 구성합니다. 등록·검색·물건 상세·위치 선택·임시 저장·계정·삭제·오류에도 같은 토큰을 적용하세요. 현재 위치와 이름의 가독성을 사진·브랜드 장식보다 우선합니다.

사진 선택 취소는 오류가 아닙니다. 이름·위치 저장과 사진 전송 상태를 구분하고 사진 자동 재시도 3회 실패 후에는 재시도를 제공하세요. 계정당 임시 저장은 하나이며 서버 완료와 기기 보존을 구별하세요. 수정 충돌을 조용히 덮어쓰거나 복구·실행 취소 기능을 추가하지 마세요. 생성 미리보기를 실제 로그인·저장·업로드 구현으로 표시하지 마세요.
```

## 형식 검증 범위

사용자가 제공한 생성 화면과 [OpenDesign 공개 파서](https://github.com/nexu-io/open-design/blob/53231d40b778d88eba23f35547bf99485d3ae9fc/apps/web/src/runtime/design-md-parse.ts), [frontmatter 파서](https://github.com/nexu-io/open-design/blob/53231d40b778d88eba23f35547bf99485d3ae9fc/apps/daemon/src/design-systems/frontmatter.ts)를 참고해 구성했다. 영문 섹션명과 Role·Name·Hex·Usage 색 표, Display/Body font 및 Voice·Imagery·Layout 레이블을 사용한다. 화면이 연결한 [DESIGN.md 예시 모음](https://github.com/VoltAgent/awesome-design-md)도 확인했다.

공개 파서를 로컬에서 실행해 이름·기본 팔레트·서체·문구·이미지·레이아웃과 YAML 토큰이 읽히는지 확인했다. kit 팔레트 파서는 같은 hex를 합치고 최대 12색을 요약하므로 핵심 12색을 먼저 배치했으며 전체 역할은 YAML과 원본 문서에 유지했다. 설치된 OpenDesign의 버전별 입력·생성 결과는 아직 확인하지 않았고 이번 요청에서는 앱에 자료를 입력하거나 생성을 실행하지 않았다. 문서 전용 변경으로 TDD와 Flutter 테스트·분석·빌드는 제외한다.
