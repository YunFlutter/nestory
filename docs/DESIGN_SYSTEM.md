# Nestory 디자인 시스템 제안

2026년 10월 1일 작성한 사용자 검토용 제안이다. 한국어 Android·iPhone 앱의 등록·찾기·이동 흐름을 일관되게 디자인하기 위한 기준이며, 앱에 구현된 디자인 시스템이나 승인된 최종 UI를 뜻하지 않는다. [Issue 3](https://github.com/YunFlutter/nestory/issues/3)에서 진행하며 [MVP 기획](PRODUCT_PLAN.md)의 정책을 따른다.

## 제안 방향

순백색 바탕과 차콜 글자·버튼을 중심으로 구성하고, 채도를 낮춘 브릭은 작은 브랜드 표식에만 사용한다. 사용자의 그린 제외, AI스럽게 느껴지는 색 조합 제외, 국내 앱을 참고한 흰색 바탕 요청을 반영한 제안이다. 웜화이트·베이지의 넓은 바탕 대신 흰색 화면과 무채색 회색 구분을 사용한다. 이는 모든 한국 사용자나 국내 앱의 색 선호를 일반화한 결과가 아니다. 블루·살구 조합, 파스텔 장식, 그라데이션, 광택 있는 3D 소품을 제거하고 사진·한글·현재 위치가 화면의 중심이 되게 한다.

[디자인 연구](DESIGN_RESEARCH.md)의 출처와 화면별 적용안을 바탕으로 역할별 색, 한글 타이포그래피, 공통 컴포넌트, 상태·모션과 검증 방법을 이 문서에서 구체화한다. UI UX Pro Max 검색 결과는 한국어와 Nestory 정책에 맞게 검토하며 최종 선택을 그대로 자동 확정하지 않는다.

## 컬러 토큰

그린 계열을 제외하고 주요 동작·선택·성공·정보를 중립색으로 구성했다. 성공은 차콜과 체크 아이콘·완료 문구로 표현하며 주요 행동과의 차이는 컴포넌트 구조로 구별한다. 브릭은 브랜드 표현에만 사용하고 오류의 붉은색과 같은 컴포넌트에서 경쟁시키지 않는다. 현재 제안은 라이트 모드 기준이다. 다크 모드 지원을 이번 문서로 확정하지 않는다. 승인 이후 역할별 다크 토큰과 실제 화면의 대비를 별도로 설계해야 한다.

| 토큰 | 값 | 사용 |
| --- | --- | --- |
| `background` | `#FFFFFF` | 페이지 기본 바탕 |
| `surface` | `#FFFFFF` | 카드·시트·팝업 바탕 |
| `surfaceSubtle` | `#F5F5F5` | 사진 미등록 영역·입력의 보조 바탕 |
| `textPrimary` | `#292724` | 이름·제목·현재 위치 |

| `primary` | `#292724` | 저장·추가·이동 확정, 선택 아이콘 |
| `onPrimary` | `#FFFFFF` | primary 위 글자·아이콘 |
| `primaryPressed` | `#151412` | primary 버튼을 누른 상태 |
| `primaryContainer` | `#F4F4F4` | 선택 목적지·활성 항목 바탕 |
| `onPrimaryContainer` | `#292724` | 선택 영역의 글자·아이콘 |
| `accent` | `#985343` | 작은 브랜드 일러스트·장식 |

| `divider` | `#E9E9E9` | 장식적 행 구분, 상태 식별용으로 사용 금지 |
| `focus` | `#292724` | 밝은 바탕 위 2px 포커스 표시, 2px 간격 |

| `success` / `successContainer` | `#292724` / `#FFFFFF` | 서버 저장·이동 완료 |

| `error` / `errorContainer` | `#A23C34` / `#FFFFFF` | 실패·삭제 위험 |

페이지·카드·시트는 흰색을 유지하고 보조 영역과 선택만 밝은 무채색 회색으로 구분한다. 상태 안내는 흰 바탕에 의미가 있는 글자·아이콘과 해결 행동을 제공한다. 페이지·본문·행동·선택은 중립색을 유지한다. 브릭은 작은 브랜드 표현에만 사용한다. 색 면적을 채우기 위한 장식 패널이나 여러 파스텔 카드, 그라데이션은 사용하지 않는다. 버튼과 상태 배경에 같은 보조색을 무분별하게 쓰지 않는다. 성공·실패·대기는 아이콘과 문구를 함께 표시한다. 공간별 무지개색이나 색상만으로 공간·보관함·물건을 구별하는 방식은 채택하지 않는다.

포커스 색은 주변 바탕에 따라 적용한다. primary 버튼에는 흰 내부선과 외부 primary 선을 함께 사용해 버튼과 바깥 바탕 모두에서 구분되게 한다. 사진 위에는 중요 문구와 컨트롤을 직접 겹치지 않고 불투명한 surface 영역에 둔다. 임의 투명도를 더한 상태는 별도로 대비를 계산한다.

## 대비 계산

불투명 sRGB 색쌍에 [W3C의 텍스트 대비 계산](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)을 적용한 결과다. 채널을 0~1로 정규화하고 0.04045 이하에서는 12.92로 나누며 그 밖에서는 `((c + 0.055) / 1.055)^2.4`로 선형화한다. 상대 휘도는 `0.2126R + 0.7152G + 0.0722B`, 대비는 `(밝은 휘도 + 0.05) / (어두운 휘도 + 0.05)`다. 아래 표는 표시값만 소수 둘째 자리로 반올림했다.

| 앞 색과 바탕 | 계산 대비 | 적용 |
| --- | --- | --- |
| textPrimary / background | 14.89 대 1 | 본문 통과 |
| textSecondary / background | 6.10 대 1 | 보조 본문 통과 |
| textSecondary / surfaceSubtle | 5.59 대 1 | 보조 본문 통과 |
| onPrimary / primary | 14.89 대 1 | 버튼 본문 통과 |
| onPrimary / primaryPressed | 18.41 대 1 | 버튼 본문 통과 |
| onPrimaryContainer / primaryContainer | 13.54 대 1 | 선택 본문 통과 |
| onAccent / accent | 5.75 대 1 | 보조 본문 통과 |
| success / successContainer | 14.89 대 1 | 상태 본문 통과 |
| warning / warningContainer | 6.89 대 1 | 상태 본문 통과 |
| error / errorContainer | 6.50 대 1 | 상태 본문 통과 |
| info / infoContainer | 6.67 대 1 | 상태 본문 통과 |
| outline / background | 3.54 대 1 | 비텍스트 경계 통과 |
| outline / surfaceSubtle | 3.25 대 1 | 비텍스트 경계 통과 |
| onDisabled / disabledContainer | 3.86 대 1 | 비활성 전용, 본문 4.5 기준 미달 |

일반 텍스트는 4.5 이상, 상태 식별에 필요한 아이콘과 경계는 [비텍스트 대비](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)의 3 이상을 설계 기준으로 삼는다. 이 계산은 전체 앱의 접근성 인증이 아니다. 글자 확대·사진·합성·포커스·스크린리더는 구현 후 확인해야 한다.

## 한글 타이포그래피

서체 후보는 [Pretendard](https://github.com/orioncactus/pretendard)다. 저장소에 폰트를 추가하지 않았으며 도입 시 SIL Open Font License의 고지와 파일 구성, Android·iPhone의 실제 표시를 검토한다. 전용 영문 디스플레이 서체를 본문과 섞지 않는다.

| 역할 | 크기와 줄 높이 | 굵기 | 용도 |
| --- | --- | --- | --- |
| display | 32 / 42 | 700 | 소개·큰 빈 상태 제목, 일상 화면에는 제한 |
| title | 24 / 34 | 700 | 화면 제목·물건 이름 |
| section | 20 / 28 | 600 | 보관함·물건 섹션 제목 |
| body | 16 / 24 | 400 | 입력값·메모·본문 |
| label | 16 / 24 | 600 | 버튼·주요 행 이름 |
| bodySmall | 14 / 22 | 400 | 경로·필드 안내 |
| caption | 12 / 18 | 500 | 부가 정보, 핵심 위치·오류에는 사용 금지 |

수치는 Flutter 논리 픽셀 기준의 출발값이며 플랫폼 글자 확대를 적용한다. 모든 텍스트의 기본 자간은 0으로 두고 실제 한글 표시를 확인한다. 필수 내용에는 고정 높이·축소 글자를 적용하지 않는다. 경로는 전체 값에 접근할 수 있어야 하며 검색 결과에서는 여러 줄을 허용한다. 글자 확대 시 공간 카드는 1열로 바꾸고 행·버튼·필드의 높이를 늘린다.

## 간격과 형태

- 간격은 `4, 8, 12, 16, 24, 32, 40, 48`을 사용한다. 항목 내부 8·12, 일반 그룹 16, 섹션 24·32가 출발값이다.
- 좌우 여백은 기본 20, 좁은 화면 16을 제안한다. 360·390·430 너비를 검토 기준으로 삼되 고정 화면 크기로 UI를 늘이거나 줄이지 않는다.
- 카드·사진 radius 16, 입력·버튼 12, 시트 상단 24, 작은 상태 레이블 8을 사용한다. 모든 요소를 pill로 만들지 않는다.
- 버튼·탭 가능한 행·아이콘의 터치 영역은 최소 48×48 논리 픽셀로 제안한다. 시각 아이콘 24, 보조 아이콘 20을 사용하고 의미 레이블을 제공한다.
- 목록 사진은 56×56, 공간 사진은 4 대 3 비율, 상세 사진은 원본 비율을 유지하면서 화면에 맞춘다. 사진 자르기가 대상을 숨기면 전체 보기 경로를 제공한다.
- 기본 카드에는 그림자 대신 여백과 divider를 사용한다. 시트·팝업에만 필요한 깊이를 주며 구체 그림자·scrim은 실제 바탕에서 검증한다.
- 안전 영역·키보드·뒤로 가기 영역을 먼저 확보한다. 하단 저장 버튼에 가려지는 내용이 없도록 스크롤 여백을 둔다.

| 확인 창 | 대상·결과·취소·명시적인 확인 | 포커스 관리·뒤로 가기, 복구 불가 안내, 위험 행동을 기본 선택으로 두지 않음 |
| 빈 상태 | 유형 그래픽·짧은 안내·해결 행동 | 첫 공간 추가·내부 물건 추가·검색어 수정 등 맥락별 행동 |

컴포넌트는 화면 동작을 보조한다. 저장 성공 후 화면 전환 실패, 이동 중 취소, 요청 취소와 재시도 식별의 상세 규칙은 구현 Issue에서 결정해야 하므로 이 문서에서 임의로 확정하지 않는다. 안내 컴포넌트가 서버 규칙 검증을 대신하지 않는다.

## 상태와 한국어 문구

| 실제 상태 | 표시 제안 | 제공할 행동과 유지 원칙 |
| --- | --- | --- |
| 등록 요청 진행 | `저장하고 있어요` | 성공 전 완료 표시 금지, 입력 유지 |
| 서버 텍스트 저장 완료 | `이름과 위치를 저장했어요` | 사진 상태가 별도로 남으면 함께 표시 |
| 사진 전송 대기 | `사진 전송을 기다리고 있어요` | 저장된 이름·위치 유지, 연결 복구 시 재시도 정책 |
| 사진 자동 재시도 3회 실패 | `사진을 보내지 못했어요. 다시 시도해 주세요` | `재시도`, 앱 재실행으로 수동 상태 초기화 금지 |
| 사진 선택 취소 | 선택 이전 상태 유지 | 오류 표시 없음 |
| 카메라 권한 거부 | `사진을 찍으려면 카메라 접근을 허용해 주세요` | 허용할 방법 안내, 사진 없이 계속 입력 가능 |
| 임시 저장 서버 완료 | `임시 저장했어요` | `계속 작성`·`삭제`, 계정당 하나 |
| 임시 저장 기기 보존 | `이 기기에 보관했어요. 연결되면 동기화해요` | 다른 기기에서 아직 볼 수 없음을 추가 설명 |
| 캐시 결과 조회 | `이 기기에 저장된 내용만 보여요` | 완전한 검색 결과와 구분, 온라인 변경 제한 설명 |
| 이름 오류 | `이름을 입력해 주세요` 또는 `이름은 50자까지 입력할 수 있어요` | 해당 필드에 오류 연결 |
| 수정 충돌 | `다른 기기에서 내용이 바뀌었어요` | `최신 내용 확인`, 조용한 덮어쓰기 금지 |
| 비어 있지 않은 위치 삭제 | `안에 있는 보관함과 물건을 먼저 옮기거나 삭제해 주세요` | 삭제 진행 불가 이유 안내 |
| 물건 삭제 확인 | `이 물건을 삭제할까요? 삭제한 기록은 복구할 수 없어요` | `취소`·`삭제`, 실행 취소 없음 |
| 탈퇴 확인 | `탈퇴하면 물건과 위치 기록을 복구할 수 없어요` | 비밀번호 재확인 후 삭제 시작 |
| 탈퇴 정리 진행 | `계정과 기록을 정리하고 있어요` | 서버 정리 완료 전 전체 성공으로 숨기지 않음 |

설명은 짧은 해요체, 버튼은 `저장`·`계속 작성`·`이 위치로 이동`처럼 행동을 표현한다. 상품 안내나 금융 전문 용어를 가져오지 않는다. 안내의 간결함 때문에 사진 실패·서버 미동기화·복구 불가 등의 사실을 생략하지 않는다.

## 모션과 그래픽

| 역할 | 출발값 | 동작과 제한 |
| --- | --- | --- |
| 누름 반응 | 120ms | 색·불투명도, 내용과 터치 경계는 이동시키지 않음 |
| 상태 교체 | 180ms | 필요한 영역만 교체, 진행 문구를 숨기지 않음 |
| 계층 탐색 | 260ms | 진입·뒤로 가기의 공간 방향 유지, 내용 접근을 지연하지 않음 |
| 사진 연결 | 260ms | 카드와 상세의 같은 사진을 이어 보임, 사진 없음은 일반 전환 |
| 시트 | 240ms | 짧은 선택에 사용, 긴 탐색은 충분한 화면 공간을 확보 |

시간은 테스트할 시작값이며 모든 애니메이션의 고정 정책이 아니다. 큰 탄성·자동 반복·패럴랙스·페이지 전체 블러는 기본 화면에서 사용하지 않는다. OS의 애니메이션 축소 요청에는 이동·확대를 단순화하거나 없애고 상태 의미·포커스·결과는 유지한다. 앱 종료 중 업로드를 실행하는 듯한 그래픽도 만들지 않는다.

브랜드 그래픽은 보관함·파우치·경로라는 제품 의미를 표현한다. 차콜 선과 작은 브릭 표식으로 구성한 평면 그래픽은 소개·빈 상태에서 검토할 수 있다. 광택·그라데이션·입체 렌더를 기본 그래픽으로 사용하지 않는다. 사용자 사진과 합성한 홍보 이미지, 실시간 3D와 별도 마스코트는 이번 제안에 포함하지 않는다. 구조 아이콘은 일관된 선형 계열을 사용하며 실제 아이콘 패키지 도입은 별도 검토한다.

## 화면별 적용

[화면별 연구](DESIGN_RESEARCH.md)의 홈·위치 상세·세 등록 유형·검색·물건 상세·위치 선택·임시 저장·계정·삭제 및 오류에 같은 토큰을 적용한다. 홈은 공간 카드, 위치 상세는 경로와 보관함·물건 섹션, 검색은 전체 경로가 있는 행으로 구성한다. 정렬 옵션을 바탕색 차이만으로 표현하지 않고 선택 레이블도 제공한다.

물건 상세의 주요 행동은 위치 변경이고, 사진은 보조 단서다. 홈에는 공간 추가, 현재 위치에는 물건/보관함 추가를 맥락에 맞게 배치한다. 세부 메뉴·탭 개수·기본 정렬 외의 새로운 기본값은 화면 디자인 단계에서 검토하고 확정 전 구현하지 않는다. 가족 공유·AI·QR·가격·수량·대시보드·알림·복구 기능을 추가하지 않는다.

## 검증 결과와 후속 검증

완료한 검증은 불투명 색쌍의 대비 계산과 문서·링크·변경 범위 점검이다. 문서와 정적 디자인 자산만 변경하므로 TDD 제외이며 Flutter 분석·테스트·플랫폼 빌드는 실행 대상이 아니다.

구현 후 작은/큰 iPhone과 Android 화면, 키보드·안전 영역·뒤로 가기·가장 큰 글자 크기·VoiceOver·TalkBack·키보드 포커스를 확인해야 한다. 보관함 최대 깊이와 50자 이름·1,000자 메모, 사진 없음과 동명 항목, 긴 전체 경로를 확인한다. 실패·충돌·기기 보존·수동 사진 재시도 상태는 재실행 이후에도 실제 데이터와 일치해야 한다. 성능은 profile 모드와 실기기에서 측정한다.

사용자 승인이 필요한 사항은 이 제안의 시각 방향과 팔레트, 서체, 컴포넌트 형태다. 기존 제품 정책은 이 문서에서 변경하지 않는다. Material·Cupertino 기반, 다크 모드, 폰트/아이콘 의존성, 상세 작업 취소 정책은 승인 또는 후속 Issue에서 정한다.

## 이미지 보드

[디자인 시스템 이미지](design/nestory-design-system-board.png)는 이 제안을 검토하기 위한 정적 요약이다. 정확한 hex·수치·상태 의미의 원본은 위 문서이며 생성 이미지의 글자·색·폰트 모양을 구현 사양으로 추출하지 않는다. 이미지에서 주장하는 명암비는 원본 토큰 계산값이며 이미지 픽셀의 접근성을 검증한 값이 아니다.

사용한 내장 이미지 생성 도구의 [전체 프롬프트](design/DESIGN_BOARD_PROMPT.md)를 함께 보관한다. 이미지 생성 결과를 검사하고 문서와 다르거나 읽기 어려운 부분은 기록한다. 앱 화면 구현이나 전체 사용자 흐름의 검증 결과가 아니다.

최종 보드는 1,448×1,086 PNG다. 흰색 페이지·밝은 무채색 회색 선택·차콜 버튼/성공·작은 브릭 표식, 주요 한국어 레이블과 대비 표기를 시각적으로 확인했다. 생성 결과 일부 색 면에 미세한 명암이 남아 있으므로 앱 구현에서는 문서의 단색 토큰을 그대로 사용한다. 이미지의 Pretendard 표기는 서체 후보 설명이며 실제 폰트 적용 검증은 아니다.

흰색 바탕 수정 보드에서는 기본 바탕을 `순백색`으로 표기했다. 생성 이미지의 hex 오자 보정이 유지되지 않아 해당 이미지 라벨을 교체했으며 정확한 배경값은 `#FFFFFF`다. 페이지·카드·상태 안내의 흰색 바탕과 무채색 선택 영역, 대비 14.89 대 1 표기를 시각적으로 확인했다.

OpenDesign에 입력할 때는 토큰과 생성 지침을 합친 [DESIGN.md](../DESIGN.md)와 [필드별 입력 자료](design/OPEN_DESIGN_INPUT.md)를 사용한다. 이 입력용 문서는 같은 제안의 표현 형식이며 별도 팔레트나 앱 구현이 아니다.
